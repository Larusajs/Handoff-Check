# Observe a real usage pilot

Use a disposable copy or explicitly approved read-only project plus metadata
outside the application checkout. Review real documented constraints deliberately;
do not infer policy from arbitrary source text. Keep private paths, rules, owner
names and reports out of public examples.

Prepare reviewed content-aware handoffs and, when wanted, explicit review/source
registries through existing commands. Preserve originals. Record the invocation,
selected scope/profile, tool version and observed exit/output without claiming a
human review happened merely because a command passed.

Try default check (maintenance not requested), all selected checks, a deliberately
changed rule, a changed bound source in a disposable copy, and malformed optional
metadata. Never refresh a baseline merely to clear a finding. Compare application
file hashes and Git state before/after; check itself must not write anything.

Use the [observation template](pilot-observation-template.md). Technical smoke
checks, synthetic CI and one operator's observations do not establish usability,
time saved, recruitment success or completion across multiple repositories.
Record unresolved limitations and distinguish measured facts from opinions.
